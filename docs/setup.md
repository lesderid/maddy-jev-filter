# Setup

## Requirements

- maddy, tested with 0.9.6, with its imapsql storage.
- `ldc2` and `rdmd`. `rdmd` comes from
  [dlang/tools](https://github.com/dlang/tools); build the tag that matches
  your compiler's frontend (`ldc2 --version`), for example:

  ```sh
  ldc2 -O -release rdmd.d -of=rdmd && sudo install -m 755 rdmd /usr/local/bin/
  ```

- A Jev API key from [TypeSafe](https://docs.typesafe.ai).

## Installing

Install the filter from a git checkout. This copies it to
`/usr/local/lib/maddy-jev-filter` and records the commit in `VERSION`, which
ends up in every header. Use `-H HOST` to install on another machine:

```sh
tools/install.sh -H mail.example.org
```

Then the config and API key, on the mail server:

```sh
sudo install -m 644 -o root -g maddy /usr/local/lib/maddy-jev-filter/jev-filter.example.json /etc/maddy/jev-filter.json
sudo install -m 640 -o root -g maddy /dev/stdin /etc/maddy/jev-filter.key <<< "$JEV_API_KEY"
```

See [Configuration](configuration.md) for what to change in it.

maddy's systemd unit gives the script a private `/tmp`. `rdmd` compiles the
script there on the first message after each maddy restart or install, which
takes about 7 s and 400 MB. After that each run takes about 10 ms plus the
Jev request.

## maddy.conf

Add the check to the pipeline that delivers to local mailboxes, not to the
SMTP endpoint. Checks on the endpoint run alongside maddy's own SPF and DKIM
checks, before their results are in the message:

```
msgpipeline local_routing {
    check {
        command /usr/local/lib/maddy-jev-filter/maddy-jev-filter.d check {msg_id} --sender={sender} --rcpts={rcpts} --auth-user={auth_user} --source-ip={source_ip} {
            # Exit code 1 means "reject" by default; if rdmd can't even compile
            # the script, deliver the message instead.
            code 1 ignore
        }
    }
    ...
}
```

Write the options as `--name={placeholder}`, so an empty or dash-prefixed
value can't be mistaken for something else. Mail from logged-in users
(`--auth-user`) and bounces generated by maddy (empty `--source-ip`) is
passed through untouched, since `local_routing` handles those too.

With only the check in place, every message gets the header and a log line,
but nothing moves yet. That's a good way to watch the verdicts for a while.
To start routing, add the filter to the storage:

```
storage.imapsql local_mailboxes {
    ...
    imap_filter {
        command /usr/local/lib/maddy-jev-filter/maddy-jev-filter.d route {msg_id}
    }
}
```

### Quarantined mail

maddy's own checks can quarantine a message: SPF failing, a DMARC policy, a
sender domain without MX records. maddy then delivers it straight to Junk
and skips the `imap_filter`, so it stays unread and has no `route` log line.
Jev sees the SPF result anyway, so you can leave SPF failures and missing MX
records to the filter:

```
smtp tcp://0.0.0.0:25 {
    ...
    check {
        require_mx_record {
            fail_action ignore
        }
        ...
        spf {
            fail_action ignore
        }
    }
}
```

On the author's mail, all 24 messages SPF quarantined in a month still went
to Junk that way, and 8 of 9 without MX records; the ninth was a real
sign-in mail from a Firebase app.

## Folders

Folders named in the rules must exist. If one doesn't, maddy silently
delivers to INBOX. The example config needs Suspicious and Sports:

```sh
sudo -u maddy /usr/local/bin/maddy imap-mboxes create user@example.org Suspicious
sudo -u maddy /usr/local/bin/maddy imap-mboxes create user@example.org Sports
```

Not interested needs a folder and a timer of its own, and the lists of
senders you've kept or junked mail from a timer; see
[Learning from your mailbox](learning.md).

## Marking as read: a maddy bug

maddy's storage applies `\Seen` from an IMAP filter to the message's flags,
but not to the count of unread messages it keeps separately. Clients show
the message as read, while folder counts (IMAP STATUS) still count it as
unread, until something changes its flags. This is a bug in go-imap-sql's
delivery path
([foxcpp/go-imap-sql#52](https://github.com/foxcpp/go-imap-sql/issues/52));
IMAP APPEND handles it correctly. Until it's fixed upstream, build maddy with
the fix from that issue:

```sh
git clone https://github.com/foxcpp/go-imap-sql && cd go-imap-sql
git checkout 9e8acb0253ee   # the version maddy 0.9.6 uses
# apply the delivery.go change from the issue
cd .. && git clone --branch v0.9.6 https://github.com/foxcpp/maddy && cd maddy
go mod edit -replace github.com/foxcpp/go-imap-sql=../go-imap-sql
./build.sh --static build
```
